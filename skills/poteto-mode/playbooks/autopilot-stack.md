### Autopilot-stack

**You own the stack, never the landing. Run `playbooks/autopilot-full.md` without the merge: build and verify the queue with full autonomy, then hand the operator one linear stack they review and land themselves.** For "autopilot-stack", "stack them, don't ship", "build the stack, I'll land it". Stack chains resolve natively via `gh pr` or `origin pr` (when Origin resolves the repository) without requiring Graphite (`gt`).

1. **Run the owner loop unchanged.** Resolve the forge once (`gh` default, or `origin pr` when `command -v origin` succeeds and Origin resolves the repository). Never require Graphite (`gt`). One `poteto-agent` subagent per PR owns its change end to end: build, PR creation per `playbooks/opening-a-pr.md`, self-proof (gates, CI, receipts), skeptical Bugbot triage per `../references/bugbot-triage.md`, `/deslop`, `/no-comments`, and babysit to green per `playbooks/babysit.md`. Owners parallelize when work is self-contained and only stack when a PR builds on another PR. Every owner keeps a `decisions.tsv` trail per the **show-me-your-work** skill in the brain store (`<appDataDir>/brain/<conversation-id>/decisions.tsv` or root agent store), never committed, returned in its report.
2. **Audit on the wake chain.** The root runs an audit tick roughly every 30 to 60 minutes via Antigravity's `schedule` tool (`DurationSeconds="1800"` or recurring cron, `TimerCondition: "never"`), `/goal`, or `/loop 1h` until no delegated work remains. Name this file in every tick prompt so each tick sees the no-merge rule. Never leave the cadence to memory or lossy notifications. At each tick, re-read this playbook from trunk with `git show origin/main:skills/poteto-mode/playbooks/autopilot-stack.md` and re-read the armed `/goal`. Fix record drift as urgent. Probe active owners via `send_message` or inspect `manage_subagents(Action: "list")` on tick or watchdog timeout, counting only side effects as progress (commits, pushes, PR or check deltas, and store reports). Treat an agent as stuck when it errors, cannot start turns, shows no side effect past its expected runtime, or has neither pushed nor written a trail row by the first tick. Terminate and replace a stuck owner or lane at once. Conclude each active tick that changed state with a `/ketchup` report under 100 words summarizing chain progress with linked artifacts and open operator decisions, keeping no-op ticks quiet, and yield immediately. Disarm the scheduled cadence only when no delegated work remains.
3. **Hold the operator gates.** State-then-wait, so a request to state the plan is not a go. On the operator's explicit go, arm a `/goal` with the full program objective. On the operator's stop, every owner takes an immediate zero-writes hold.
4. **Verify at STACK-READY.** The owner reports `STACK-READY` with the exact head SHA, branch, and parent branch. The root verifies that SHA once with a full swarm at code-ready per the Local fan-out section of `skills/poteto-mode/references/antigravity-tools.md` (or `/cloud-swarm` for more than 8 lanes): parallel independent verifiers re-running gates, a live runtime floor (`browser_subagent`, CLI execution, or verify skill), and a receipts-and-diff audit distrusting the PR body. A rebase, conflict fix, or minor fix gets a single verifier, and wording-only changes get none. Pre-existing base problems do not block unless the PR copies or newly reaches them (per `playbooks/autopilot-full.md`). Findings go back to the owner, and nothing enters the stack unverified.
5. **Append on a clean verdict, never ship.** No owner merges, arms auto-merge, or closes. A clean verdict appends the PR to the one linear reviewed chain, in verified order or an order the operator specified.
6. **Single writer on topology, parallel writers on builds.** Base each PR on its parent PR's branch (with the stack root based on trunk) per `playbooks/opening-a-pr.md`. Each owner pushes only its own branch (`git push --force-with-lease` after checking `ls-remote`) and reports its tip and intended parent branch. The root owns stack topology and wires PR base branches via `gh pr edit <pr> --base <parent-branch>` or `origin pr edit <pr> --base <parent-branch>` (Graphite tracking is optional only, never required).
7. **Absorb drift at the root, then re-verify what moved.** When trunk or a lower PR moves, rebase the stack root onto trunk and each child PR onto its parent PR's branch (pushing with `--force-with-lease`). When a restack hits conflicts in an owner's files, that owner fixes its slice. Compare `git patch-id` at each verdict SHA against the new head per `playbooks/shipping.md`. An unchanged `git patch-id` preserves the verdict (though each new head still needs green CI), while anything that drifted re-runs step 4 before delivery. Countersigns follow `playbooks/autopilot-full.md`.
8. **Deliver the chain.** Stop when each PR is verified and green at its current head, with every link carrying its verifier verdict in the PR body or a comment. Hand the linear reviewed chain to the operator to inspect and land. After handoff, nobody pushes without the operator's go. When delivery completes, disarm the scheduled audit tick.

**Choosing between the autopilots.** Autopilot-full when PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** links to the stack root and tip, each PR with its head SHA and one-line verdict summary, anything parked or excluded with the reason, and trail paths.
